# 配信PCのセットアップ・運用手順

このアプリは配信PC内のHono、SQLite、OBSで動きます。企画／CMの切替は管理画面から手動で行います。映像ファイルはPCに置いたまま再生し、外部サーバーへアップロードしません。

## 初回セットアップ

### 1. OBSの準備

1. OBS Studioを起動します。
2. **ツール → WebSocketサーバー設定**でWebSocketサーバーを有効にします。既定ポートは `4455` です。認証を使う場合は、設定したパスワードを確認します。
3. **シーンコレクション → インポート**から、リポジトリの `obs/collections/shikosai.json` を読み込みます。
4. `茨香祭ローカル配信` コレクションを選び、シーン `企画` と `CM` があることを確認します。
5. `ステージ映像` のキャプチャデバイスや画像など、配信PC固有のOBSソースを調整します。`CM映像`、`telop`、`配信オーバーレイ` のソース名は変更しないでください。CM動画は再生時に `CM映像` へ設定されます。

### 2. Hono管理画面を起動

Node.js 22 LTSをインストールし、リポジトリのフォルダでPowerShellを開きます。

```powershell
cd .\shikosai-signage-api
npm install
npm run dev
```

既定ではリポジトリ直下の `CM` フォルダを使います。別のフォルダに置く場合は、Honoを起動する前に同じPowerShellでパスを指定して起動します。

```powershell
$env:SIGNAGE_MEDIA_ROOT = "..\CM"
npm run dev
```

管理画面: <http://127.0.0.1:8787/admin>

OBSブラウザソース: <http://127.0.0.1:8787/broadcast>

管理画面とOBSは同じPCで起動してください。サーバーは `127.0.0.1` だけで待ち受けます。Honoの終了はPowerShellで `Ctrl+C`、OBSの配信開始・停止はOBS側で行います。

### 3. 管理画面のローカル設定

1. 管理画面の **ローカル設定** を開きます。
2. OBS WebSocketのポートをOBS側と合わせます。パスワード認証が有効ならパスワードを入力して **接続設定を保存**。認証を使わない場合は空欄にし、保存済みパスワードがある場合は削除チェックも選びます。
3. OBSの接続表示が「接続中」になることを確認します。
4. `企画シーン` に `企画`、`CMシーン` に `CM` を選びます。シーンの選択はその管理画面を開いているブラウザに保存されます。
5. 開催日、CM候補の自動選択、サークルカット表示を設定して保存します。サークルカット表示は **CMと同期** または **独立表示** を選べます。

接続情報は `shikosai-signage-api/data/obs-connection.json`、企画・CM・お知らせなどは `shikosai-signage-api/data/signage.sqlite` に保存します。どちらもGit管理対象外です。

## 本番データを登録

### 企画タイムテーブル

1. **企画タイムテーブル → CSVテンプレート**をダウンロードします。
2. Excelで企画名、説明、開始時刻、変更後の開始時刻、開催日、クラス・団体名などを入力します。変更がなければ変更後の開始時刻は空欄にします。
3. **CSV UTF-8（コンマ区切り）**で保存し、管理画面から読み込みます。
4. 既存の本番タイムテーブル全体を置き換える場合は、読み込み前に **選択日の既存タイムテーブルを置き換える** を選びます。
5. 配信管理のタイムラインで時刻と表示を確認します。各行の **▶ 設定** から、その企画の編集画面をすぐ開けます。

CSVの列は `title,description,scheduled_start,adjusted_start,day,class_name,kind,circle_slug,media_path` です。`title` と `scheduled_start` は入力してください。`kind` は通常企画なら `program`、CM枠なら `break` です。CM枠の長さは次の企画の開始時刻までで計算します。

初回起動時には表示確認用のデモ企画が入ります。デモ行には `DEMO` と表示され、OBSの配信データには出ません。本番前に必ず実際のタイムテーブルを読み込んでください。

### CM素材

1. CM動画を運用PCの `CM` フォルダに置きます。
2. **CM素材**でCM名、フォルダからの相対パス（例: `club-name.mp4`）、再生秒数、紐づくクラス・サークルを登録します。
3. CMの希望度を `-10`（流したくない）〜`+10`（よく流したい）で設定します。クラス・サークル側の希望度も **クラス・サークル情報** から調整できます。
4. 本番で使うCMを有効にします。初期デモCMは無効です。

CMシーンへ切り替えると、次の企画までの残り時間に収まり、優先度が高く、最近の再生や同じCM枠内の重複が少ない候補を選んで再生します。1枠あたりの同一サークル上限も反映します。時刻になってもシーンは自動で切り替わらないため、企画／CMのボタン操作は運営スタッフが行います。

### お知らせ・団体情報

- **お知らせ**に配信文を入力します。文章はAIで変更せずそのまま使います。緊急区分は先頭に強調表示されます。長文は配信画面で2列表示になります。
- クラス・サークル情報は初回起動時に公式HPの公開テキストからSQLiteへ登録されます。再取り込みする場合は `seed/shikosai-catalog.json` を選びます。画像データは取り込まず、画像の参照先だけを保持します。

## 当日の操作

1. OBSとHonoを起動し、配信管理画面でOBSが接続中か確認します。
2. タイムラインと配信情報を確認します。
3. 企画開始時は **企画**、CMに入る時は **CM** を押します。CMに切り替えると、残り時間に応じたCMがOBSの `CM映像` から再生されます。
4. CMから企画へ戻すときは **企画** を押します。CM再生は停止します。
5. 配信画面は <http://127.0.0.1:8787/broadcast> をOBSのブラウザソースに表示します。`?demo=1` は表示確認専用です。

配信を始める前にOBSのプレビューと音声・映像ソースを確認し、OBS側で配信を開始してください。

## バックアップとトラブル確認

- **ローカル設定 → ローカル設定バックアップ** で運営データのJSONスナップショットを作成します。保存先は `shikosai-signage-api/data/backups/` です。映像・画像の実体とOBS接続パスワードは含まれません。CM動画は別途PC内で保管してください。
- OBSが接続しない場合は、OBSのWebSocket有効化、ポート、認証設定と管理画面の入力を照合します。
- シーン切替に失敗する場合は、OBSシーン選択で `企画`／`CM` が表示されることを確認します。
- CMが再生されない場合は、CMが有効か、ファイルパスとファイルの存在、CMシーンの `CM映像` ソース、CM候補自動選択の設定を確認します。
- OBSブラウザソースが空の場合は、Honoを起動したまま、ソースURLが `http://127.0.0.1:8787/broadcast` か確認します。
